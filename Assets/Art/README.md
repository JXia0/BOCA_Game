# BOCA art upload guide

This folder is the only production destination for visual assets. Artists should upload source files and exported PNG files here, keep the matching Unity `.meta` files, and push both through GitHub.

## Folder ownership

```text
Assets/Art/
  Shared/                         Reused by every chapter
    Backgrounds/                  Shared environmental layers
    UI/                           Dialogue frame, buttons, panels
    Icons/                        Evidence, source, warning and navigation icons
    Fonts/                        Licensed bitmap display fonts only
    VFX/                          Fades, glints, gentle water and notification effects
  Chapters/
    Chapter01_OilTide/
    Chapter02_SpermWhaleRescue/
    Chapter03_ReefWarning/
    Chapter04_HawksbillGuzheng/
      Backgrounds/
      Characters/
      Portraits/
      CG/
      Props/
      UI/
```

Do not place chapter-specific art in `Shared`. Do not create another `Assets/Images`, `New Folder`, or desktop-export folder.

## Pixel production standard

- Compose backgrounds and CGs at 320 x 180 pixels, 16:9. Unity displays them at integer scale when possible.
- Draw scene characters around 32 to 40 pixels high. Use a consistent ground line and bottom-center pivot.
- Draw dialogue portraits at 64 x 64 pixels. Keep the silhouette readable and leave room around hair, instruments, and animal anatomy.
- Export transparent PNG files at 1x scale. Also submit the layered `.aseprite` or `.psd` source when used.
- Use hard pixel edges. Do not add AI upscaling, blurred resizing, JPEG artifacts, premultiplied halos, or smooth vector-like outlines.
- Body text is generated by Unity and must not be painted into backgrounds, UI panels, phone screens, documents, or screenshots.
- Protected animals must be species-accurate and restrained. Do not make oiling, stranding, seizure, or illegal trade cute or comedic.
- All marketplaces, accounts, order numbers, addresses, brands, and private information must be fictional.

## Naming and automatic binding

The sprite name is its stable art key. Use the exact asset ID at the beginning of the filename, for example:

```text
C4_ENV_01_concert_hall.png
C4_POR_02_friend.png
C4_CG_01_hawksbill_information.png
```

After importing art, run `BOCA > Art > Rebuild Art Catalogs`. Production scenes will bind any sprite whose name matches the key in the chapter flow. A duplicate key is a blocking error.

Recommended Unity import settings:

- Texture Type: Sprite 2D and UI
- Sprite Mode: Single unless the file is an approved sprite sheet
- Pixels Per Unit: 16
- Filter Mode: Point
- Compression: None
- Generate Mip Maps: Off
- Alpha Is Transparency: On for transparent PNG files

## Git handoff

1. Pull the latest branch before drawing against a scene.
2. Put files in the correct chapter and category folder.
3. Open Unity once so `.meta` files are generated and inspect the import settings.
4. Commit the art file, source file when applicable, and every matching `.meta` file together.
5. Use a clear commit summary such as `<create> chapter 4 concert hall background` or `<feat> chapter 2 whale breathing animation`.
6. Push the branch and tell the integrator which asset keys were added or replaced.

Never delete or regenerate another artist's `.meta` file. Never overwrite a file while changing its meaning; create a new versioned key if the scene needs a genuinely different asset.
